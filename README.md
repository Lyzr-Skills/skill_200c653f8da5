# florida-material-risk: bounded first-question revision

Install this ZIP in place of (not alongside) the existing `florida-material-risk` skill. Keeps Scenario 1 as the implicit scenario. Primary change: the original first-question path tried a material × time read and, when that failed, fell back to as many as 26 weekly paged reads. The new path attempts only a narrowly filtered, bounded server-side read; after timeout it does not cascade into a full-week loop or claim full coverage. LIMIT alone does not ensure low server cost. If 26 weeks cannot be read interactively, a saved exception view / read-only export is the recommended infrastructure solution. This is a performance-safety improvement, not a proven reduction in server latency; it can return incomplete results if the backend cannot perform a fast full scan.

No live model timing tests were run when this package was built. Test the first question both on a cold session and a warm session and record wall-clock duration, tool calls, returned row count, pagination, coverage, error reason, and whether requested measure was unmet demand or actual forecast inventory. Compare with the old version; never reward an untrue 'complete' report merely because it was quick.
